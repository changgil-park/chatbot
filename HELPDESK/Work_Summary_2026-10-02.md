# HELPDESK 작업 정리 (2026-10-02, 대시보드 데이터 탭)

## 한 줄 요약
HELPDESK 대시보드에 HDK 테이블의 실시간 적재 현황을 보여주는 **데이터 탭**과 **작업 내역 카드**를 추가했다. 서버는 Zio SDK 로 DB 를 읽는 읽기 전용 API 4개를 새로 냈다. 상태는 커밋 전이다.

## 변경 파일
| 파일 | 내용 |
|---|---|
| `HELPDESK/main.py` | 정적 서버에 읽기 전용 API 와 `/manual_images` 서빙 추가 (+104줄) |
| `HELPDESK/admin/index.html` | 데이터 탭 UI, 작업 내역 카드, 계획 체크 항목 추가 (+184줄) |
| `HELPDESK/Agent_Context.md` | 이번 작업의 결정·제약·미해결 기록 |
| `WorkLog.md` | 완료 한 줄 추가 |

## 서버 API (`HELPDESK/main.py`)
| 경로 | 역할 |
|---|---|
| `GET /api/health` | 상태 확인. `sdk` 필드로 Zio SDK import 여부를 알려준다. |
| `GET /api/overview` | 문서별 조각·지식 건수와 kind 분포, 테이블 전체 건수. `refresh=1` 이면 캐시를 비우고 다시 센다. |
| `GET /api/modules?docID=` | 화면 행의 `attrJson` 을 집계한 모듈(장)·그룹별 화면 수. |
| `GET /api/know` | 지식 행 검색 (`docID`, `kind`, `q`, `limit` 최대 100). |
| `GET /api/chunk/{id}` | 원문 조각 본문과 미리보기 이미지 위치. |

- 쓰기 API 는 없다.
- 사용자 입력은 `where` / `where_or` 의 값 자리로만 들어간다.
- `overview`, `modules` 는 30초 캐시한다.
- SDK import 가 실패해도 정적 화면은 뜨고 API 만 503 을 돌려준다.
- 이미지는 `/manual_images/<문서명>/{pages,embedded}/` 로 서빙한다.

## 대시보드 화면 (`admin/index.html`)
- **개요 탭 · 작업 내역 카드.** `WORKS` 배열로 완료한 일 7건을 커밋 해시와 함께 보여준다. 마지막 항목(데이터 탭)만 "커밋 전" 상태다.
- **데이터 탭 · 요약 카드.** 적재 문서 수와 총 쪽수, 조각 수, 지식 수, 검수 상태(검수 전)를 보여준다.
- **데이터 탭 · 적재된 문서와 분포.** 문서별 현황 목록과 지식 종류별 분포 막대·범례를 보여준다.
- **데이터 탭 · 모듈별 화면 수.** 문서를 선택하면 모듈별 막대가 나오고, 마우스를 올리면 그룹별 수가 보인다.
- **데이터 탭 · 지식 탐색.** 문서·종류·키워드로 검색한다. 행을 누르면 관계·메뉴 경로, 원문 조각, 페이지 미리보기, 화면 캡처 6장이 우측에 나온다.
- **계획 탭.** Phase 1 에 "대시보드에 적재 현황·지식 탐색 연결 (데이터 탭)" 항목을 완료로 추가했다.

## 확인된 제약과 미해결
- `HELPDESK/manual_images/` 는 git 에 없다. 다른 환경에서는 이미지가 뜨지 않는다.
- 지식 행 중 `(이름 없음)` 소제목, 문장 전체가 subject 가 된 행이 있다. `lzxp_loader.py` 의 소제목 판정 규칙을 개선해야 한다.
- `PHASES` 체크 상태는 인덱스 기준(localStorage)이다. 중간에 항목을 끼우면 저장된 체크가 어긋나므로 새 작업은 단계 맨 끝에 추가한다.
- 이번 작업은 변경 내용을 코드로 확인해 정리한 것이며, 정리 시점에 서버를 다시 띄워 화면을 검증하지는 않았다.

## 참고
- `HELPDESK_ingest/main.py` 가 새 파일(untracked)로 남아 있다. 플랫폼이 자동 생성하는 파일로 보이며, 이번 대시보드 작업과는 별개다.
- 변경은 아직 커밋하지 않았다. 의미 단위는 "대시보드 데이터 탭 추가" 한 건이다.
