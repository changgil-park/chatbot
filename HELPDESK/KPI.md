- 작성일: 2026-10-02
- 상태: **초안 (사용자 확정 전)**. 목표값은 **가안**이며, 현재 수치(기준선)를 모르는 항목은 Phase 0에서 측정한 뒤 확정한다.

## 1. 목표

> 오프라인에 흩어진 도움말을 **한 곳에서 묻고 답을 얻는 지식 체계**로 바꾸고, 반복되는 문제는 **에이전트가 직접 해결**한다.

| 층 | 목표 | 1차/2차 |
|---|---|---|
| G1. 지식화 | 도움말 파일을 빠짐없이 구조화된 지식(온톨로지)으로 전환한다 | 1차 |
| G2. 답변 품질 | 사용자 질문에 **정확하고 근거가 있는** 답을 준다 | 1차 |
| G3. 업무 효과 | 사람이 문서를 찾고 답하는 수고를 줄인다 | 1차 (측정은 운영 후) |
| G4. 자동 해결 | 반복되는 문제를 도구 호출로 직접 해결한다 | 2차 |

## 3. 지표 정의와 측정 방법

### G1. 지식화

| ID | 정의 | 산식 | 측정 방법 |
|---|---|---|---|
| K1 | 적재 대상 파일 중 적재 완료 비율 | 적재 문서 수 ÷ 대상 파일 수 | `Zio.entity("HDK_DocMST").count()` 와 원본 폴더 파일 수 대조. 청크 수가 0인 문서는 실패로 센다 |
| K2 | 청크 중 분석이 끝난 비율 | `anlSt=완료` 청크 ÷ 전체 청크 | `HDK_ChunkMST` 의 `anlSt` 집계 |
| K3 | 추출된 노드·엣지가 원문과 맞는 비율 | 정확 건수 ÷ 검수 건수 | 노드 종류별로 무작위 표본(종류당 30건)을 사람이 원문과 대조 |
| K4 | 근거 청크가 달린 노드 비율 | `EVIDENCED_BY` 가 있는 노드 ÷ 해당 종류 전체 | `Zio.node(...).optional_out("EVIDENCED_BY")` 로 없는 것을 센다 |
| K5 | 같은 뜻인데 따로 선 노드 비율 | 중복 노드 수 ÷ 전체 노드 수 | 이름 유사도로 후보를 뽑아 사람이 판정 |

### G2. 답변 품질

모든 G2 지표는 **평가 질문셋**을 기준으로 한다.

- 구성: 대표 질문 **30~50개** (문서에 답이 있는 질문 + 없는 질문 약 20%)
- 각 질문에 **정답 요지와 정답 근거 위치**를 사람이 미리 적어 둔다
- 문서가 갱신될 때마다 같은 질문셋으로 **회귀 측정**한다

| ID | 정의 | 산식 |
|---|---|---|
| K6 | 정답 요지를 포함하고 틀린 내용이 없는 답변 | 정답 수 ÷ 질문 수 |
| K7 | 답변에 문서명과 위치(페이지·슬라이드·시트)가 있는 비율 | 출처 포함 답변 ÷ 전체 답변 |
| K8 | 그래프·근거에 없는 내용을 사실처럼 말한 답변 | 환각 답변 ÷ 전체 답변 |
| K9 | 문서에 없는 질문에 모른다고 답한 비율 | 적정 미응답 ÷ 문서 밖 질문 |
| K10 | 질문 입력부터 답변 완료까지 시간 | 로그의 응답 시간 P90 |

### G3·G4. 운영 지표

| ID | 정의 | 측정 방법 |
|---|---|---|
| K11 | 사용자가 추가 문의 없이 종료한 비율 | 대화 로그에서 "해결됨" 표시 또는 재문의 없음으로 판정 |
| K12 | 답변 아래 도움됨/아님 응답 비율 | 피드백 값 집계 |
| K13 | 문의 접수부터 해결까지 걸린 시간 | **기준선이 필요하다.** 현재 담당자가 처리하는 시간을 2주간 표본 측정 |
| K14 | 모르겠다고 답한 질문을 보강한 비율 | 미응답 질문 목록 대비 문서·그래프에 반영된 건수 |
| K15 | 도구로 해결 가능한 유형 중 실제 자동 해결된 비율 | 도구 호출 로그 + 결과 확인 |
| K16 | 도구 호출이 오류 없이 끝난 비율 | `Zio.tools.execute` 성공 ÷ 호출 |
| K17 | 사용자 의도와 다르게 시스템을 바꾼 건수 | 도구 호출 로그와 사용자 확인 기록 대조 |

## 4. 이 KPI를 위해 설계에 더해야 할 것

KPI를 측정하려면 **대화·호출 기록**이 있어야 한다. 현재 [Plan.md](Plan.md) 4.3의 테이블 가안에는 없으므로 **`usr` 테이블 컬럼이 확정되기 전에** 추가해야 한다 (컬럼 추가·삭제 불가).

| 테이블(가안) | 용도 | 주요 컬럼 |
|---|---|---|
| HDK_ChatLogMST | 질문·답변 기록 (K6~K12) | chatID, sessionID, question, answer, srcList(출처), respMs, feedback(도움됨/아님), resolvedFg, regUid, regDt |
| HDK_ToolLogMST | 도구 호출 기록 (K15~K17) | callID, chatID, toolID, argJson, resultSt, confirmFg(사용자 확인 여부), regUid, regDt |
| HDK_EvalQMST | 평가 질문셋 (K6~K9) | qID, question, expectedAns, expectedDoc, hasAnsFg(문서에 답이 있는 질문인지) |

- 위 테이블은 가안이며, Plan.md 4.3에 반영할지는 사용자 승인 후 정한다.
- 개인정보가 질문에 섞일 수 있으므로 질문 로그의 보관 기간과 마스킹 방침을 정해야 한다 (미결).

## 5. 단계별 완료 판정

| 시점 | 통과 조건 |
|---|---|
| Phase 1 완료 | K1 = 100% |
| Phase 2 완료 | K2 ≥ 95%, K3 ≥ 90%, K4 = 100% |
| Phase 3 완료 (1차 종료) | K6 ≥ 80%, K7 = 100%, K8 ≤ 3%, K9 ≥ 90% |
| 시범 운영 1개월 | K11, K12, K13 측정 시작, 2차 도구 대상 선정 |
| 2차 완료 | K15 ≥ 50%, K16 ≥ 95%, K17 = 0건 |

기준 미달이면 다음 단계로 넘어가지 않고 해당 단계 안에서 원인을 찾는다 (프롬프트·추출 규칙·청크 분할 등).

## 6. 가정과 한계

- 목표값은 **업계 일반 수준을 참고한 가안**이며 이 조직의 기준선 데이터는 없다. 확정은 Phase 0에서 샘플로 측정한 뒤 한다.
- K3, K6, K8은 **사람이 판정**해야 해서 표본 크기만큼 검수 시간이 든다.
- K11~K13은 챗봇이 실제 업무에 투입돼야 측정된다. 1차 개발 기간에는 측정할 수 없다.
- 평가 질문셋은 **담당자가 만든 질문**이라 실제 사용자 질문과 분포가 다를 수 있다. 운영 로그에서 실제 질문을 주기적으로 질문셋에 추가한다.

## 7. 사용자 결정이 필요한 지점

1. G1~G4 목표 구성과 ★ 표시한 1차 KPI가 맞는지
2. 목표값(가안) 중 조정할 것. 특히 K6 정답 80%, K8 환각 3%
3. 현재 헬프데스크 업무의 기준선을 잴 수 있는지 (K13 용: 문의 건수, 처리 시간)
4. 평가 질문셋을 만들 담당자 (질문과 정답 요지를 작성할 사람)
5. 대화 로그 테이블(4장)을 설계에 추가할지, 질문 로그 보관·마스킹 방침
